# Проверка интеграции

## Среда и установленный клиент

Проверка 21 ноября 2026 года прошла в EndeavourOS x86_64, XFCE/X11, на HP 255 G8 с Ryzen 7 5700U и интегрированной графикой. Установлены `yandex-music 5.109.1-1`, `pulsesync-bin 3.1.0-1`, mpv `1:0.41.0-6` и mpv-mpris `1.3-1`. Перед тестом Яндекс Музыка и PulseSync были закрыты. Яндекс Музыка запущена обычным исполняемым файлом в существующей пользовательской сессии. Установочные файлы, данные PulseSync и профили не изменялись Overtone. Токены не запрашивались.

Клиент Яндекс Музыки зарегистрировал `org.mpris.MediaPlayer2.chromium.instance…` с идентичностью `YandexMusic`. При ошибке загрузки данных и попытке включить «Мою волну» снимок оставался `Stopped`, `CanControl=true`, `CanPlay=false`, `CanPause=false`, `CanGoNext=false`, `HasTrackList=false`, список схем `OpenUri` пуст, метаданные текущего трека отсутствуют. На машине был включён VPN. В логе клиента также появился `ENOENT` для `app-update.yml` при проверке обновлений. Эти наблюдения не устанавливают причину поломки плагинов PulseSync. Присутствует резервная копия `app.backup.asar`, на момент проверки совпадавшая с текущим архивом. Проверка не устанавливала факт активного мода.

## Два подтверждённых локальных пути

1. Обычный mpv с mpv-mpris. `OpenUri` открывает выбранную запись по HTTP с локального тестового сервера. Для A и B получены нужные URI, а `PlayPause` подтвердился состояниями `Playing → Paused → Playing`. В объявленных схемах mpv-mpris есть `http` и `https`, `file` отсутствует. Открытие через `OpenUri` создаёт другую очередь. [Спецификация MPRIS Player](https://specifications.freedesktop.org/mpris/latest/Player_Interface.html)
2. Адаптированный mpv. Стартовый хук `on_load` подставляет вычисленную Rust-ядром цель в `stream-open-filename`; имя исходного элемента очереди остаётся прежним. IPC сообщает состояние после `playback-restart`. При ошибке открытия хук `on_load_fail` делает одну попытку исходного потока. Реализация mpv 0.41.0 требует отличающегося URI для повторного открытия, поэтому для локального оригинала используется эквивалентный путь с `/.`. Хук ограничен проверенной версией. [Документация mpv](https://mpv.io/manual/stable/#hooks), [реализация mpv v0.41.0](https://github.com/mpv-player/mpv/blob/v0.41.0/player/loadfile.c)

```bash
dbus-run-session -- python3 tests/smoke.py target/release
```

Нужны mpv, mpv-mpris, FFmpeg и PulseAudio-совместимый сервер. Тест создаёт изолированную сессионную шину, два плеера, временные XDG-каталоги и отдельный виртуальный аудиовыход. A — 440 Гц, B — 880 Гц, C — 660 Гц. Тест захватывает PCM с monitor source, проверяет потоки B, C и A и сверяет список очереди с A, C по IPC. Настоящие пользовательские записи и профиль плеера не нужны.

## Как продолжить проверку Яндекс Музыки

1. Когда клиент может загружать и воспроизводить записи с действующей пользовательской сессией, запустите выбранный трек A в Яндекс Музыке.
2. Запустите `overtone-ctl probe`, затем `overtone-ctl probe ИМЯ_ПЛЕЕРА PlayPause` дважды. Ожидается переключение `Playing → Paused → Playing`.
3. Проверьте `track.uri` и `schemes`. Если клиент не передаёт URI, вставьте ссылку оригинала вручную для сохранения правила. При наличии объявленной схемы HTTPS попробуйте `overtone-ctl probe ИМЯ_ПЛЕЕРА OpenUri https://music.yandex.ru/track/ID` с выбранной доступной альтернативой B. При успехе проверьте фактическое звучание и состояние очереди.
4. Для автоматической замены Яндекс Музыки требуется отдельно подтверждённая точка до старта аудио. Рабочего адаптера для desktop и браузера в этой сборке нет. При проверке mpv звук идёт только через выбранный экземпляр mpv и его локальные записи. Веб-сессия не исследовалась на доступном для воспроизведения аккаунте.

## Границы функций

- На новом mpv версия адаптера перепроверяется. При несовпадении версии автозамена выключается, данные и базовые возможности MPRIS сохраняются.
- История создаёт завершённую запись после переключения, остановки или полного выхода. Медиа-события mpv различают повторную загрузку того же файла. У обычного MPRIS идентичность ограничена переданными событиями и перемотка к началу не всегда отличима от намеренного повтора.
- Таймер запускается в фоне и привязан к уникальному владельцу имени на той же сессионной шине. При завершении фонового процесса активный таймер сбрасывается.
- В X11 сохранение положения и режим поверх окон доступны через EWMH. В Wayland эти действия зависят от оконного менеджера.
- Прямые ссылки HTTPS на аудио реализованы, но живой путь с удалённым аудио не подтверждён. Плейлисты и страницы каталогов не являются поддержанным форматом аудиозамены.
